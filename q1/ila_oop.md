# ILA 3-1: Applying the Four Pillars of OOP

## Sari-Sari Store Inventory System

### 1. Encapsulation
- This can be used to group items into one unit which avoids the hassle of having too much or too many variables. Encapsulation also allows the reader to not be confused due to the amount of variables, thus making it easier to read through. updateStock() and getPrice() can be used as methods.

### 2. Abstraction
- This can be really helpful with checkout processes, because it hides the unnecessary details and backgrounds, for example; calculations, database, etc. Abstraction only shows things that are highly relevant only. We could use functions as pressCheckout() as a method, and others such as removeFromSheets().

### 3. Inheritance
- This prevents the repetition of the code for different kinds of retail items. This allows the programmer to code a general code and make new branches of code down to others. This can be put the product into parent class such as name, costPrice, and ExpirableProduct as a child class.

### 4. Polymorphism
- This lets the checkout list be more smooth and efficient through one general command, although these items are separated and the costs are calculated differently. Polymorphism in this case can be used with the methods calculateFinalPrice() and calculateInitialPrice() for the individual items themselves.

### Reflection:
Studying the OOP pillars, I think that encapsulation is probably the most helpful when going back to the Sari-Sari store problem. Encapsulation is basically summarizing everything and it makes it efficient for the seller and for the programmer to organize items through code. The items would be too messy and disorganized without encapsulation because without the grouping, everything would be really confusing and end up being difficult to understand for everybody in that situation.
